### The seam extension, and why it was unavoidable

`render()` gates on closure variables (`configured`, `sb`, `session`, `notCoach`, `offline`, `draft`, `view.name`). None of them were reachable, and `WSTRAIN_ENGINE` exported no `render`. Without four more properties the harness can draw exactly nothing but a session card in isolation, so "cover every view" is not achievable. Added at index.html:2322: `render`, `startPool`, `hydrate`, `setUi`. No markup, no CSS, no new UI, nothing the coach can reach. It cannot conflict with pass 2. The alternative was regex surgery on the app source from inside verify.js, which rots the first time a line moves.

### The bug the harness found on its first run

index.html line 2092 painted a proposed set's cue with `style:{color:"var(--accent-ink)"}`. **`--accent-ink` does not exist.** Pass 1 renamed that token to `--accent-text` in the stylesheet and missed this one JS string, so Claude's proposed cues render in the inherited colour. Fixed to `var(--accent-text)`. It is now check number 4 of section 17, and mutant 6 of section 18 reintroduces it on purpose to prove the check bites.

### Proof it cannot mask a regression

Three independent arguments, all executed rather than asserted:

1. **Section 18 is inside the suite.** It loads six deliberately broken copies of the app into six separate sandboxes and demands the failures appear. Two of the six change only a name, never a word on screen: those must slip past section 16 and be caught by section 17, and the check fails if section 16 also fails, which would mean the control is not isolating anything. Every mutant also self-checks that its `from` string still exists in the app, so a rename in pass 2 cannot quietly turn the control into a no-op.

## Items

### 1. fakeEl(), verify.js:227  [rewritten, four real behaviours added]

Additions and the reason for each. (a) `firstChild` is a getter over `children` and `removeChild` really splices and nulls `parentNode`: `clear()` is `while (node.firstChild) node.removeChild(node.firstChild)`, so with the old no-op pair **clear() did nothing at all** and every view drew on top of the last one. Any content check would have passed on leftovers from the previous screen, which is the single biggest masking risk in the old stub. (b) `textContent` is a getter/setter over the subtree (get concatenates descendants, set replaces children with one text node, matching the DOM): the harness has to read what the coach reads, and the app writes it directly at `clock.textContent = mmss(el)`. (c) `listeners` recording in `addEventListener`, because `h()` routes every `onclick` through it: this is what lets the suite press the tabs, tap a block on the deck and press Close, and what makes "no view paints a button with nothing behind it" possible. (d) `setAttribute` mirrors `id`, `class` and `value` onto properties, as a browser does, because `h()` routes all three through `setAttribute`; without the `value` mirror the date field reads empty and the default-date promise cannot be checked. Plus `tagName`, `parentNode`, `attrs`, and a real `contains`. `querySelector` still returns null and `querySelectorAll` still returns `[]`, and `classList`, `innerHTML`, `dataset`, `closest`, `matches`, `getBoundingClientRect` are still absent, so the engine still may not use them.

### 2. element identity, verify.js:288 parseBody + makeEnv:394  [fixed, deliberately]

**Decision: identity now survives, and the document is parsed out of index.html's own `<body>` rather than hand written.** `getElementById` walks that tree and returns the node itself or **null**. Three reasons, each of which is a check that is otherwise impossible. (1) `render()` does `var pool = document.getElementById("pool"); if (pool) pool.remove();`. With a fresh object per call the branch always ran against a phantom, the real overlay was never removed, and a second `#pool` stacked on the first, a dead black screen on the deck, was invisible. The suite now asserts exactly one overlay while open, still one after a re-render, and zero after Close. (2) A renamed markup id was invisible: the app asked for "app" and always got something back. It now fails at index.html:2356 with `#app missing`, and the load itself throws with a pointed message. (3) Parsing the real markup means the ids and classes section 17 checks are the ones that ship, and cannot drift from a hand-written fixture. Cost: the app now genuinely needs `#app` and `#who` to exist at load, which is the correct contract.

### 3. determinism: FrozenDate verify.js:355, makeTimers:362  [added]

Two new sources of nondeterminism had to be closed before any view could be checked. **The clock is frozen** to `2026-11-01T12:00:00Z` and settable: the app asks the real clock for the default date on the Today screen, for whether `fmtDate` prints a year, and for how far through the session the pool view thinks it is. It is deliberately a **Sunday**, which is not one of his class days, so `todayISO()` and `nextClassISO()` are two different answers and a screen that muddles them cannot pass (verified: swapping `nextClassISO()` for `todayISO()` in the date field now fails). The expected next class day is computed from the frozen instant, not typed in. **Timers are a queue, not real**: `poolState.timer = setTimeout(tick, 1000)` would otherwise reschedule once a second for the rest of the run, and the clock could not be advanced under control. `runOne()` fires exactly one tick, which is how "90:00" and the behind-schedule inversion get checked. Freezing the clock also removed a pre-existing time bomb: the export check in section 12 behaved differently once the calendar rolled into 2027.

### 5. section 17, verify.js:1360 to 1421 analyse()  [new, 6 checks, the bug class the review called invisible]

The sweep harvests every class, id and inline `var(--token)` the engine actually assigned, across all twelve screens plus the two classes that only exist after a tap (`done`, `behind`). Those are then held against the stylesheet that shipped in the same file. Six checks: every `getElementById("x")` target exists in the markup or is an id the engine creates; **every id the stylesheet targets is an id something actually has** (catches `#pool` drifting from the overlay in either direction); **every class the engine assigns is a class the stylesheet styles**; every token an inline style reaches for is defined; every token the stylesheet reaches for is defined; and every token in use has a plain definition, **not only one inside a media query** (a themed token left defined only inside the dark block is missing for everyone in light mode, which on a bright pool deck is most people). The reverse direction, styled but never painted, is **printed and not failed**: today it reports `.center` and `.info` as dead CSS, and failing on it would fight every half-finished pass 2 edit.

### 7. index.html:2092, --accent-ink  [bug found by the new harness, fixed]

### 8. limitation: partial class rename  [known, documented behaviour]

A class counts as styled if it appears in **any** selector in the stylesheet. `.blk` has eight rules; renaming one of the eight leaves the class styled by the other seven and is not caught. A wholesale rename is caught (verified for `.blk`, `.pblk`, `.goalbox`). Same shape for tokens: defined anywhere counts as defined, except the media-query dimension, which is checked. Going further would need real cascade resolution, which is out of scope for a regex harness in a zero-build project.

### 9. limitation: no layout, no pixels  [known, unchanged]

The stub has no geometry and no computed style, so the harness still cannot see 44px tap targets, contrast ratios, overflow, z-order, safe-area insets or the `backdrop-filter` guard. It sees structure, text, classes, ids, handlers and tokens. The pass 1 work that IS now protected is the part expressible in those terms: the `.codeblock` class with no inline background, the `.login` class, `isLive` in the library and insights counts, the pool `done` class and the behind-schedule inversion, and the token system's integrity. Everything measured in pixels or contrast still needs the eye.
